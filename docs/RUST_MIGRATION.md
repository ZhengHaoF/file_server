# Rust 后端迁移说明

迁移目标为独立 Rust 服务与同域 Web 管理端，移除对 Tauri 桌面外壳的设想。用户已允许放弃不合理的旧兼容设计，但有效接口不因语言迁移而无意义改名；具体保留和改动以 `shared/RUST_API.md` 为准。

## 升级顺序

- **先备份**：备份旧私有配置、凭据文件和数据库，记录旧服务启动方式、监听地址与共享目录。用户原文件保持原地，不复制到服务源码目录。
- **隔离部署**：使用新的私有数据/缓存目录和另一个本机端口启动 Rust，先保持文件写入和上传关闭。共享目录可以相同，但测试删除、改名和上传只能使用独立临时目录。
- **验证客户端**：核对文件列表、分页、中文与特殊文件名、登录、图片缩略图、视频拖动，以及管理端概览/日志/配置/任务/会话。升级前不要把测试服务暴露到公网。
- **切换服务**：停止旧服务，再切换端口或代理。为 Rust 配好系统服务、容器重启策略或显式监督模式；没有监督者时不启用 Web 重启能力。
- **再开启写入**：确认运行身份和目录权限、目标文件系统支持安全不覆盖发布，随后显式打开 `writeEnabled`，上传还需 `uploadEnabled`。

## 有意改变的运行设计

- **运行时**：默认服务入口改为 Rust 二进制，不再需要 Node/npm 启动服务；Vue 前端仍需要 Node 在构建阶段生成静态资源。
- **管理入口**：只有浏览器入口，没有桌面窗口和托盘。服务未运行时由操作系统或容器启动，不由无法加载的 Web 页面负责。
- **路径语义**：相对路径依据配置文件目录或可执行文件目录解析，避免不同启动工作目录造成共享位置改变。迁移时推荐显式绝对路径。
- **进程指标**：状态返回运行时标识和版本；Rust 没有 Node 的 V8 heap 指标，前端显示不可用，不用零值伪装。
- **媒体依赖**：不依赖 Node Sharp 或 npm 的 FFmpeg 安装包，目标机需要 libvips CLI、vipsheader 和 FFmpeg；Docker 镜像安装它们。
- **私有数据**：Rust 使用独立 data/cache，凭据、日志、后台配置和数据库不混入静态目录。首次使用新 data 目录会生成新凭据；不要把旧演示密码迁过来。
- **派生缓存**：Rust 使用自己的缓存版本和管理记录。迁移不承诺逐文件复用旧 Node 缓存；保留旧缓存供回退，新服务按需重建，不批量重算全部媒体。
- **文件读取协议**：新版客户端使用 `/api/v2/files?path=`、`/api/v2/content?path=` 与 `/api/v2/preview?path=&kind=&width=&height=`，不再用 `$` 表示根目录、不再在原文件路径尾部拼接 `!尺寸`。根目录由空 `path` 表示，目录名 `$` / `$$` 和文件名中的 `!` 保持字面意义。旧路由仅是 Rust 的过渡入口，新客户端不向旧 Node 自动回退。
- **浏览器会话隔离**：文件登录与管理登录使用不同的 HttpOnly cookie，避免在同一浏览器登录文件端后覆盖管理会话、导致后台实时日志断开。Bearer 会话和只读媒体票据仍只保存在客户端内存，管理端不读取 cookie 内容。
- **HTTPS失败处理**：显式开启`httpsEnabled`但证书、私钥或端口不可用时，整个服务拒绝启动并返回78；不会悄悄退回HTTP。内置supervise遇78停止重启。请先在隔离端口验证证书，再切换正式服务；故障时从宿主机修正配置。
- **资源约束**：每个监听器最多256个活跃连接，图片/视频生成分别最多4/2个并发，超时和等待队列均有界。图片源限制6400万像素，超过返回413；视频采用容器格式白名单，不支持HLS/concat播放列表作为截图源。大图与特殊视频编码需使用自己的样本验证，不承诺语言重写带来NAS性能提升。
- **原生客户端凭据迁移**：下载队列的旧URL会移除票据和userinfo，再用当前内存会话续接；新缩略图不把带票据URL写入磁盘图片缓存。旧版本已生成的磁盘缓存不会自动抹除，升级后建议清理旧应用图片缓存，并重新登录，使旧票据撤销或等待到期。不要把清理应用派生缓存误当成删除原文件。

## 回退与限制

当前源码已移除旧 Node 后端、旧静态产物、旧打包脚本和专用 CI。Git 历史仍保留完整旧版；需要回退时先停止 Rust，在独立目录检出迁移前版本（本轮起点提交 `844f355` 或对应发行版），使用对应旧客户端与备份的旧配置/独立旧数据目录启动；不能只把当前版本后端换成 Node 而继续使用 v2 客户端。不要让两个进程并发写同一个数据库或缓存目录，不把 Rust 的新配置覆盖文件直接交给旧服务读取。

文件写入本身不能通过语言回退撤销，因此切换前应保留备份并先只读验证。此工程不承诺抵御恶意本地进程的挂载点/路径替换竞态，也不是多租户权限系统。

验收只报告实际完成的检查：本地 Linux 测试、黑盒 HTTP 与浏览器检查，与远端 Windows/Flutter/ARM 结果分开。没有在实际 NAS 上执行的压力测试、平台测试或备份恢复不能标为完成。
