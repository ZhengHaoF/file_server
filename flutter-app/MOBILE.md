# 手机端开发与发布

手机文件页面使用 `MobileFileBrowser`，桌面页面仍使用独立的 `DesktopFileBrowser`。业务 API、认证、传输模型共用，手机提供底部导航、当前目录搜索、长按选择和非破坏性批量下载；未开放批量删除。

## 连接与传输

- “连接并验证”允许公开只读服务器留空令牌。地址不接受内嵌账号密码、查询参数和片段；原始访问令牌与会话令牌不持久化。
- 上传任务保存入队时服务器地址，并按 FIFO 执行。切换服务器后，原服务器的待执行任务会失败并提示切回，不会改投新服务器。旧格式任务没有服务器身份，必须重新创建。
- 下载完成后 Android 保存 MediaStore URI，点击记录由系统应用打开；移除记录及临时预览不会删除公共目录副本。iOS 保存到应用文档目录的 Downloads，系统“文件”应用可访问。
- 传输仍是前台队列，重启应用后未结束任务标记失败，需要重试；没有后台传输保证、断点续传或相册自动备份。
- 上传采用 2 分钟进度空闲保护，不用固定 60 秒限制整个视频发送。未收到成功确认时应核对服务器目录，再决定是否重试。
- 文本预览支持 UTF-8 本地文件和 HTTP/HTTPS，最多 2 MB，超限请下载后打开。

## Android 签名

CI 的 `flutter build apk --debug` 仅为开发测试包，不是正式发布版本。release 不再静默使用 debug 签名；正式分发需在本地创建 `android/key.properties`：

```properties
storeFile=/absolute/path/to/release.jks
storePassword=<通过本地安全方式配置>
keyAlias=<发布密钥别名>
keyPassword=<通过本地安全方式配置>
```

此文件与密钥已被 Git 忽略。没有正式签名时不能把 unsigned/release 输出当作可安装的正式版；不要提交密钥或密码。

## 平台验收边界

CI Android debug 构建和 iOS simulator 构建用于捕获编译问题，不代替设备验收。实际检查相机允许/拒绝、局域网允许/拒绝、HTTP/HTTPS 媒体加载、系统文件导出、低存储空间、锁屏和 Wi-Fi 切换。

iOS 增加相机、照片库和局域网用途说明，允许本地网络资源，不全局禁用 ATS。不同网络与媒体插件的行为仍需真机验证。Android 保留本地 HTTP 支持，应避免在不可信网络使用明文传输长期凭据。
