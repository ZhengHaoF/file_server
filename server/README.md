# 后端开发与检查

保持单机部署和现有文件接口，不为个人 NAS 引入不必要的服务。运行数据、凭据、数据库、日志和预览缓存必须位于共享原文件目录之外。

## 开发命令

```sh
npm ci
npm run check
npm run benchmark
```

`check` 依次执行 ESLint、Prettier 校验、渐进类型检查和 Node 回归测试，CI 使用同一入口。修改代码后运行 `npm run format`；lint 自动修复可用 `npm run lint:fix`。

`typecheck` 当前严格检查错误模型、HTTP 请求期限、目标锁和数值配置 schema 四个基础模块，不代表整个遗留后端已经完成类型迁移。新模块应补 JSDoc，并逐步加入 tsconfig 的检查范围；不要通过关闭 strict 或添加整文件忽略来隐藏问题。

`benchmark` 只生成临时测试目录，完成后清理，不接触真实共享文件。结果用于比较代码路径，不作为 NAS 的容量或生产延迟承诺；速度阈值不设为容易受 CI 机器影响的硬门槛，扫描次数和尾部读取量由回归测试约束。

## 代码边界

- **入口**：index.js 负责监听、日志配置和关闭；app.js 负责 HTTP 组装，不在导入时监听端口。
- **路由**：认证、参数校验、状态码和响应；业务调用通过 async 包装传递错误。
- **服务**：adminRuntime 管理维护任务，uploads 管理上传生命周期，adminConfig 与 adminLogs 分别处理配置和日志。
- **基础设施**：SQLite 封装、路径安全、目标锁、日志字节读取和请求期限。

数据库失败必须明确抛出带 cause 的 DatabaseError，不返回假 0、false 或空数组。API 对外只输出稳定错误码、通用消息和 requestId；不得输出数据库底层消息、栈、令牌、Cookie 或绝对路径。

后台任务无论排队、运行还是最终持久化失败，都必须释放内存运行锁。审计故障不能把已完成的文件操作伪装成失败，但应记录告警；审计属于本地运维记录，不是保证不丢失的合规账本。

## 日志 API

`GET /api/admin/logs` 默认保留按时间排序的兼容路径。后台界面使用 `order=append`，按文件追加顺序从尾部读取，游标定位文件身份和字节偏移；不要把追加顺序与跨文件严格时间排序混为一谈。

活跃普通文件的最近日志不再全量扫描。级别、关键词或时间过滤命中很少时，仍可能扫描较多内容；gzip 归档不可随机寻址，读取归档仍需要解压，且有 64 MiB 解压限额。

新的应用日志携带独立 eventId，历史与实时读取保持同一 ID，轮转压缩后也能去重。旧日志使用文件身份、字节偏移和内容定位，同样内容的不同记录不再折叠；旧日志首次压缩会改变文件身份，无法承诺压缩前后 ID 不变。

游标对应文件已经压缩替换或删除时返回 409，客户端应刷新，不返回看似成功但缺页的结果。

## 上传与运维

上传总期限默认 1800 秒，空闲期限默认 120 秒，字段为 uploadTimeoutSeconds 与 uploadIdleTimeoutSeconds。总期限修改需要重启，空闲期限用于新请求；普通请求仍保留 120 秒绝对期限，HTTP 头仍保留 15 秒期限，不关闭慢请求保护。

上传在目标目录生成隐藏临时文件，通过安全发布操作防止覆盖已有目标。中断时由 Multer 关闭存储流并清理临时文件，服务再做幂等清理；上传槽在存储收尾后释放。删除仍保持原有行为，尚未引入回收站或自动删除原文件策略。

`GET /health/live` 是无敏感信息的存活探测；`GET /health/ready` 只执行轻量数据库查询，不扫描共享目录。就绪不代表所有 NAS 文件可读、空间足够或预览工具完整可用，应结合实际设备检查。

建议部署后验证真实设备上的大目录、慢速大文件上传、上传中断、冷缓存预览、磁盘满和长期并发。反向代理也有自己的上传期限与大小上限，需要同步检查。
